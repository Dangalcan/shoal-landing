Core features

Everything you need to operate Kubernetes, locally.

A single, fast, native desktop app — no browser tabs, no half-finished web dashboards. Built with Electron, React 19, and TypeScript.

One-click clusters

Spin up local clusters with kind, minikube, or k3d. Switch between contexts in a dropdown. Delete them just as easily.

Live resource explorer

Browse Pods, Services, Deployments, Ingresses, and every other Kubernetes resource with live status and YAML inspection.

Logs & built-in terminal

Tail container logs in real time, attach a shell to any pod, and run kubectl from the integrated terminal without leaving the app.

Port forwarding

Forward any service or pod to localhost in one click, and manage every active forward from a single panel.

Manifest editor

Write, validate, and apply YAML manifests from an editor that knows your cluster — no copy-pasting into a terminal.

Secure by default

Sandboxed renderer, signed plugins, local-first storage. Your cluster credentials never leave your machine.

Cluster lifecycle

Everything kubectl does, without memorizing flags.

Whether you're testing an operator or running a full dev environment, the cluster tooling is first-class. Create, inspect, and delete clusters from the app — kubectl stays available when you want it.

  • Create and delete kind, minikube, and k3d clusters from the app
  • Multi-cluster context switcher with live health checks
  • Works offline — no telemetry, no login, no cloud account
  • Kubeconfig stays in ~/.kube/config
  • Auto-updates keep the app current
Get the app
# the old way
~ kubectl config use-context kind-dev-cluster
~ kubectl get pods -A --field-selector=status.phase!=Running
~ kubectl port-forward svc/api-gateway 8080:80 -n default
~ kubectl logs -f deploy/web-frontend --all-containers --tail=200
 
✓ or skip the flags — it's all one click in the app.

For plugin developers

Build a plugin in an afternoon. Sell it the same day.

A plugin is a small JS bundle: a Node module for cluster access plus a sandboxed UI. Declare the permissions you need in the manifest, sign the bundle, and publish — free or paid — to the marketplace.

  • Register sidebar items, pages, resource actions, and notifications
  • Permission-gated capabilities — users see exactly what a plugin can do
  • Licensing, trials, and payments handled by the marketplace
  • Ship free plugins, one-time purchases, or subscriptions

Architecture

Native desktop. Sandboxed plugins. Zero cloud.

Three layers, one app. Every process is isolated, every plugin is signed, and your cluster data never leaves your machine.

Main process

Electron main runs the app lifecycle and brokers every OS call — docker, kubectl, kind — through a typed IPC bridge.

Renderer UI

A sandboxed React 19 app powered by Vite, Tailwind v4, and React Router. No Node APIs, no fs, no escape.

Plugin runtime

Plugins are cryptographically signed bundles with declared permissions. License keys and trials are handled by the marketplace backend.
